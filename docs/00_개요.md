# 00. 개요: 전체 흐름 한눈에 보기

이 문서는 프로젝트 전체를 처음 보는 사람을 위한 안내다. 각 단계의 자세한 명령과 결과는 01~05번 문서에 있다.

## 목표

- [MiniMind](https://github.com/jingyaogong/minimind)(약 64M 파라미터의 초소형 LLM)를 바탕으로 **한국어 전용 초소형 LLM**을 직접 학습해 본다.
- 실사용 모델을 만드는 것이 아니라, 노트북 GPU 한 장(RTX 5050 Laptop, VRAM 8GB)으로 LLM 학습의 각 단계를 직접 돌려 보고 이해하는 것이 목적이다.
- 원본 MiniMind 코드(`minimind\` 폴더)는 고치지 않는다. 필요한 것은 `scripts\`에 작은 스크립트를 따로 만들어 원본 함수를 불러 쓴다.

## LLM 학습 파이프라인

```
 [텍스트 데이터]
       │
       ▼
 ① 토크나이저 학습 ──── 글자를 숫자(토큰)로 바꾸는 "사전" 만들기
       │
       ▼
 ② 사전학습(Pretrain) ── 대량의 글로 "다음 토큰 맞히기" 학습 → 문장을 이어 쓰는 모델
       │
       ▼
 ③ SFT(지도 미세조정) ── 질문-답변 형식 데이터로 학습 → 대화하는 모델
       │
       ▼
 ④ 추가 학습 / 정렬 ── LoRA: 적은 자원으로 추가 학습 (미세조정 방법)
                       DPO 등: 더 좋은 답을 고르도록 다듬기 (정렬 방법)
```

## 용어집

입문자 눈높이로 간단히 적었다. 정확한 정의보다 "이 프로젝트에서 어떤 의미로 쓰였는지"에 맞췄다.

| 용어 | 설명 |
|---|---|
| **토큰 (token)** | 모델이 읽고 쓰는 최소 단위. 글자 하나일 수도, 단어 하나일 수도, 글자의 일부(바이트)일 수도 있다. 모델은 글자가 아니라 토큰 번호(숫자)만 본다. |
| **토크나이저 (tokenizer)** | 문장을 토큰으로 나누고 번호를 붙이는 도구. 일종의 "사전"이다. 어떤 데이터로 만들었는지에 따라 잘 처리하는 언어가 달라진다. |
| **BPE (Byte Pair Encoding)** | 토크나이저를 만드는 방법 중 하나. 처음엔 바이트(또는 글자) 단위에서 시작해, 데이터에서 자주 붙어 나오는 조각 쌍을 하나로 합치는 일을 반복한다. MiniMind는 바이트에서 시작하는 Byte-level BPE를 쓴다. |
| **vocab (어휘, vocab size)** | 토크나이저 사전에 들어 있는 토큰의 개수. 이 프로젝트에서는 6,400과 16,000을 만들었다. 클수록 자주 쓰는 단어를 한 덩어리로 담을 수 있지만, 모델의 임베딩(사전 크기만큼의 표)도 커진다. |
| **압축률** | 이 프로젝트에서는 "글자 수 ÷ 토큰 수". 높을수록 같은 문장을 더 적은 토큰으로 표현한다. |
| **파라미터 (parameter)** | 모델 안에서 학습으로 값이 바뀌는 숫자들(가중치). "64M 모델"은 파라미터가 약 6,400만 개라는 뜻이다. |
| **가중치 파일 (.pth)** | 학습이 끝난 파라미터 값을 저장한 파일. PyTorch 형식이다. |
| **임베딩 (embedding)** | 토큰 번호를 숫자 벡터(이 모델은 768개 숫자)로 바꾸는 표. vocab 크기 × 768 크기라서 vocab이 커지면 같이 커진다. |
| **lm_head (출력층)** | 모델의 마지막 층. 768개 숫자를 받아 vocab 전체 토큰 각각의 점수(다음 토큰일 가능성)로 바꾼다. |
| **tie_word_embeddings (가중치 공유)** | 임베딩과 lm_head가 같은 표를 함께 쓰게 하는 설정. 파라미터가 줄어든다. MiniMind는 켜져 있어서 vocab이 늘어난 만큼(vocab × 768)만 파라미터가 늘어난다. |
| **GQA (q_heads / kv_heads)** | 어텐션에서 질문 역할(query) 헤드는 8개, 참고 역할(key/value) 헤드는 4개만 두고 나눠 쓰는 방식(Grouped Query Attention). 계산량과 메모리를 줄인다. |
| **RoPE** | 토큰의 위치(몇 번째 토큰인지)를 벡터를 회전시키는 방식으로 넣어 주는 위치 인코딩(Rotary Position Embedding). |
| **RMSNorm** | 층마다 숫자의 크기를 일정하게 맞춰 학습을 안정시키는 정규화 방법. LayerNorm을 단순화한 것이다. |
| **SwiGLU** | 각 층의 FFN(피드포워드 신경망)에서 쓰는 활성화 함수 구조. 이 모델의 FFN 차원은 2,432다. |
| **MoE / aux_loss** | MoE(Mixture of Experts)는 FFN을 여러 "전문가"로 나누고 토큰마다 일부만 쓰는 구조. aux_loss는 전문가가 고르게 쓰이도록 더하는 보조 loss다. 이 프로젝트 모델은 MoE를 쓰지 않아 로그의 aux_loss가 항상 0이다. |
| **optimizer (AdamW)** | 계산된 기울기(gradient)를 보고 가중치를 실제로 얼마나, 어느 방향으로 바꿀지 정하는 알고리즘. MiniMind는 AdamW를 쓴다. |
| **loss (손실)** | 모델의 예측이 얼마나 틀렸는지를 나타내는 숫자. 낮을수록 잘 맞힌다. 사전학습에서는 "정답 다음 토큰에 모델이 준 확률"의 -log 값(교차 엔트로피)이다. 아무것도 모르고 vocab 중 하나를 무작위로 찍으면 ln(vocab) 정도가 나온다 (6,400이면 약 8.76, 16,000이면 약 9.68). |
| **epoch** | 학습 데이터 전체를 한 번 다 보는 것. 1 epoch = 데이터를 한 바퀴 돎. |
| **step** | 배치 하나를 처리하는 한 번의 학습 단위. MiniMind 로그의 step은 배치 1개 단위다. 10만 조각을 batch 16으로 나누면 6,250 step이다. |
| **batch size** | 한 step에 함께 처리하는 데이터(조각) 개수. 크면 학습이 안정적이지만 VRAM을 많이 쓴다. |
| **gradient accumulation** | VRAM이 부족해 배치를 크게 못 잡을 때, 작은 배치 여러 번의 기울기(gradient)를 모았다가 한 번에 가중치를 갱신하는 방법. batch 16 × accumulation 8이면 128개 조각마다 한 번 갱신하는 것과 비슷하다. |
| **learning rate (학습률, lr)** | 한 번 갱신할 때 가중치를 얼마나 크게 바꿀지 정하는 값. 너무 크면 학습이 불안정하고, 너무 작으면 느리다. MiniMind는 학습이 진행될수록 lr을 줄인다(코사인 스케줄). |
| **max_seq_len** | 모델이 한 번에 보는 최대 토큰 수. 이보다 긴 글은 잘리고, 짧은 글은 빈칸(padding)으로 채운다. |
| **VRAM** | GPU에 달린 메모리. 모델, 배치 데이터, 학습 중간값이 여기에 올라간다. 부족하면 batch size나 max_seq_len을 줄여야 한다. 이 PC는 8GB. |
| **bf16 (bfloat16)** | 숫자를 32비트 대신 16비트로 저장해 계산하는 형식. 메모리를 덜 쓰고 빠르며, fp16보다 표현 범위가 넓어 학습이 안정적이다. |
| **사전학습 (Pretrain)** | 대량의 일반 텍스트로 "다음 토큰 맞히기"를 학습하는 단계. 결과 모델은 질문에 답하는 게 아니라 주어진 문장을 이어 쓴다. |
| **SFT (Supervised Fine-Tuning, 지도 미세조정)** | 사전학습한 모델을 "질문 → 답변" 형식의 데이터로 추가 학습해서 대화할 수 있게 만드는 단계. |
| **LoRA** | 모델 전체를 다시 학습하지 않고, 작은 추가 행렬만 학습해서 적은 자원으로 모델을 조정하는 방법. 정렬 기법이 아니라 효율적인 미세조정 방법이며, SFT나 DPO와 함께 쓸 수 있다. |
| **DPO (Direct Preference Optimization)** | "좋은 답"과 "나쁜 답" 쌍을 보여 주고, 좋은 답 쪽을 더 선호하도록 모델을 다듬는 정렬(alignment) 방법. |
| **정렬 (alignment)** | 모델이 사람이 원하는 방식(도움이 되고, 안전하고, 형식에 맞게)으로 답하도록 다듬는 단계들을 통틀어 부르는 말. |
| **BPC (Bits Per Character, 글자당 비트)** | 텍스트 한 글자를 맞히는 데 평균 몇 비트의 정보가 필요한지. 낮을수록 좋다. vocab이 다르면 토큰 하나에 담긴 글자 수가 달라 토큰당 loss로는 비교할 수 없어서, 글자 단위로 맞춘 이 값으로 비교한다 ([05번 문서](05_vocab_비교.md)). |
| **held-out (검증 세트)** | 학습에 쓰지 않고 따로 떼어 둔 데이터. 모델이 "외운 것"이 아니라 "배운 것"을 평가하기 위해 쓴다. 이 프로젝트에서는 `data/kowiki_heldout_2k.jsonl`(2,000 조각). |
| **BOS / EOS** | 글의 시작(Begin Of Sequence)과 끝(End Of Sequence)을 표시하는 특수 토큰. 사전학습 데이터 한 조각마다 앞뒤에 하나씩 붙는다. |
| **padding** | 길이를 맞추기 위해 채우는 빈칸 토큰. loss 계산에서는 제외된다. |
| **체크포인트 (checkpoint)** | 학습 도중 저장한 모델 상태. 중간에 멈춰도 이어서 학습하거나 그 시점의 모델을 쓸 수 있다. |
