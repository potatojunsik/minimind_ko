# 대화체 평가 (100만 모델 두 개) 구현 계획

> 2026-11-20 실행 완료. 결과는 [docs/06 다음 단계 4번](../../06_데이터양_비교.md#다음-단계). 검토에서 나온 수정(띄어쓰기·문장부호만 다른 글도 묶기, 위치까지 확인하는 테스트, 텍스트만 값을 대표로)을 반영했다.

**Goal:** 위키로만 사전학습한 100만 조각 모델 두 개(vocab 6,400 / 16,000)가 한국어 대화체 답변을 얼마나 잘 예측하는지 BPB로 재고, 두 토크나이저가 대화체를 어떻게 쪼개는지 센다. 판정이 아니라 다음 단계(SFT·최종 사전학습 데이터 구성)를 위한 기준값이다.

**Architecture:** 공개 대화 데이터(`songys/Chatbot_data`, MIT)를 질문·답 쌍으로 읽고, 같은 질문이나 같은 답을 공유하는 쌍을 한 묶음으로 묶어 묶음 단위로 평가용 2,000쌍 이상을 떼어 둔다(나머지는 SFT 후보로 보관). 평가 스크립트는 `[bos] + 질문 + 줄바꿈 + 답 + [eos]`를 한 번에 넣고 답 토큰과 eos만 채점한다. 두 모델 비교는 판정 때와 같은 쌍 부트스트랩(묶음 단위, 10,000회, seed 0)으로 한다.

**Tech Stack:** Python 3.11 (.venv), torch, transformers, 기존 `scripts/eval_bpc.py`(모델 적재·fp32·창 규칙), `scripts/decide_vocab.py`(`group_by_doc`, `rate`, `bootstrap_ids`, `ci`).

**Spec:** 별도 설계 문서 없음. 근거는 docs/06 "다음 단계" 4번(이 평가 전 제목: "대화체로는 평가하지 않았다")과 2026-11-20 사용자 승인(데이터 `songys/Chatbot_data`, 질문을 문맥으로 주고 답변만 채점, 평가용 대화는 SFT에서 제외).

## Global Constraints

- 원본 `minimind/`, `tokenizers/`, `out_scale/`의 기존 파일, `data/scale/`은 고치지 않는다. 대화 데이터와 결과는 `data/chat/`(git 제외)에만 둔다.
- 판정(16,000 선택)은 바꾸지 않는다. 이 평가는 참고값이며 문서에도 그렇게 적는다.
- Δ = BPB(6,400) − BPB(16,000), 양수면 16,000이 앞섬 (docs/06과 같은 방향).
- 평가 규칙은 `eval_bpc.py`와 같다: fp32, 512토큰 창(초과 시 멈춤 — 대화 쌍은 짧아서 넘지 않아야 정상), eos 예측 포함이 기본, 텍스트만 값도 출력. (실행 뒤 변경: 결과를 보고 텍스트만 값을 대표로 바꿨다. 이유는 docs/06 다음 단계 4번.)
- 분할 시드 20261120, 부트스트랩 10,000회 seed 0.
- 문서·명령은 Windows cmd 문법과 "~다" 체로 쓴다(다른 docs와 같은 규칙).

## Review Focus

1. 질문·답 경계: 답 토큰의 위치를 정확히 골라 채점하는가(질문·구분자 토큰이 섞이면 BPB가 틀어진다). → Task 2 테스트 `test_answer_positions_only`, `test_answer_positions_exact`(위치마다 손실이 다른 가짜 모델로 채점 위치까지 확인)
2. 평가용·SFT 후보 분리: 같은 질문 문장이나 같은 답 문장이 양쪽에 동시에 있으면 안 된다. → Task 1 테스트 `test_no_shared_text_across_split`
3. 데이터 잡음: 앞뒤 공백 라벨(`'2   '`), 질문·답이 같고 라벨만 다른 중복 73행, 다시 저장한 파일의 BOM(받은 파일에는 없음), 띄어쓰기·문장부호만 다른 글. → Task 1 테스트 `test_clean_rows`, `test_groups_merge_on_near_duplicates`
4. 부트스트랩 단위: 쌍이 아니라 묶음 단위여야 구간이 좁게 나오지 않는다. → Task 3 테스트 `test_bootstrap_by_group`
5. 두 모델이 같은 평가 텍스트를 봤는지: 평가 텍스트 sha256을 두 모델 결과에 함께 기록하고 같아야 비교한다. → Task 3 테스트 `test_refuses_mismatched_eval`

### Task 2: 답변 BPB 평가

**Files:**
- Create: `scripts/eval_chat_bpb.py`
- Test: `tests/test_chat_eval.py`

**Interfaces:**
- Consumes: `eval_bpc.load_model`, `eval_bpc.WINDOW`.
- Produces: `build_ids(tokenizer, q, a, sep="\n") -> (ids, answer_start)` (질문·구분자·답을 따로 토큰화해 이어 붙임 — 경계가 합쳐지지 않게), `score_answer(model, ids, answer_start, device) -> list[float]` (답 토큰 + eos의 NLL), 결과 JSON `{tokenizer, weight, sha256, pairs: [{chars, bytes, tokens, nll, nll_eos, group, label}], tokenizer_stats}`.
- 토크나이저 통계: 질문·답의 글자/토큰, 바이트 조각 토큰 비율(토큰 하나만 decode했을 때 U+FFFD가 나오는 토큰의 비율).

- [x] Step 1: 테스트 — `test_answer_positions_only`(모든 로짓이 0인 가짜 모델이면 토큰마다 NLL = ln V. 답 NLL 합 = (답 토큰 수 + 1) × ln V, 질문 토큰 수와 무관), `test_build_ids_boundary`(ids[answer_start:-1] == tokenizer(a) 토큰), `test_too_long_pair_raises`.
- [x] Step 2: 실패 확인 → 구현 → 통과.
- [x] Step 3: 두 100만 모델로 실행(GPU). Expected: 2,000쌍 이상, 512 초과 0, 두 결과의 sha256 같음.
