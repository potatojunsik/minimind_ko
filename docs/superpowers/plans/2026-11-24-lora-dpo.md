# LoRA·DPO 체험 구현 계획

> 실행: 작성자가 이 세션에서 직접 진행한다(사용자 승인). 커밋·푸시는 설계에 적은 두 시점에만 한다.

**목표:** 최종 SFT 모델에 원본 MiniMind LoRA(자기소개)와 DPO(상투 답 줄이기)를 적용하고, 설계에 정한 항목을 측정해 docs/09에 남긴다.

**구조:** 학습은 `train_sft_ko.py`처럼 원본 `train_epoch`를 불러 쓰는 얇은 바깥 스크립트(`train_lora_ko.py`, `train_dpo_ko.py`)로 한다. 데이터는 `ChatSFTDataset`의 형식·채점 위치를 그대로 쓴다. 측정은 `eval_lora_dpo.py` 한 곳에서, 기존 함수(`generate_one`, `final_demo.generation_stats`, `eval_chat_bpb.evaluate/paired_delta/text_only`, `decide_final.eos_only`)를 재사용한다.

**기술:** Python, PyTorch, 원본 `model/model_lora.py`, unittest. **설계:** `docs/superpowers/specs/2026-11-24-lora-dpo-design.md`

## 전체 제약

- 원본 `minimind/` 파일은 고치지 않는다. 시작 모델은 `out_final/sft/sft_ko16000_768.pth`.
- LoRA: rank 16, lr 1e-4, batch 16, 20 epoch, max_seq_len 128. 데이터 학습 48쌍 + 평가 12문항, 모든 학습 답에 "MiniMind".
- DPO: 상투 답 = 9,749개 생성 답 중 20번 이상 나온 같은 답, 정답과 같으면(정규화) 제외. beta 0.1, lr 1e-6, 1 epoch, batch 8, max_seq_len 128.
- 생성은 `blind_chat_eval.generate_one`(greedy, 상한 96). 구간은 묶음 단위 쌍 부트스트랩 10,000회.
- 산출물 `out_lora/`, `out_dpo/`, `data/dpo/`(git 제외), 로그 `logs/09_*.log`.

## 확인할 실패 경우

1. 평가 12문항이 학습 질문·SFT 후보·평가 쌍과 정규화 기준으로 겹침 → 테스트로 막는다.
2. DPO 쌍에서 나쁜 답이 정답과 같음(정규화) → 선택 함수가 빼고, 테스트로 고정.
3. DPO 마스크가 답 본문 + 끝 표시가 아닌 위치를 채점 → 테스트로 고정(y와 마스크 정렬).
4. LoRA 파라미터 수가 예상(정사각 Linear 16개 × 2 × 768 × 16 = 393,216)과 다름 → 테스트로 고정.
5. 측정 때 LoRA가 실제로 켜지지 않음 → 자기소개 12문항 답이 LoRA 전후로 바뀐 수를 남긴다. 합친 모델은 fp16 반올림이 있어 logit 최대 차이와 greedy 일치 수로 기록한다.

### Task 1: LoRA 자기소개 데이터 (`docs/09_lora_identity_ko.json`)

- 형식: `{"train": [{"q","a"}×48], "eval": [{"q"}×12]}`. 질문 유형: 이름·정체, 만든 사람·목적, 학습 데이터, 할 수 있는 일·한계, 사람인지 등. 답은 짧은 존댓말 한두 문장.
- 테스트 `tests/test_lora_dpo.py::IdentityDataTest`: 개수 48/12, 학습 답 모두 "MiniMind" 포함, 평가 질문이 학습 질문·`sft_pool.jsonl`·`eval_pairs.jsonl` 질문과 `prepare_chat_eval.normalize` 기준으로 겹치지 않음, 모든 학습 쌍이 128토큰 이하.

### Task 2: LoRA 학습 (`scripts/train_lora_ko.py`)

- `train_sft_ko`의 `ChatSFTDataset`, `epoch_indices`, `check_first_batch`를 import. 원본 `trainer.train_lora` 모듈 전역(args, lm_config, model, optimizer(LoRA 파라미터만), scaler, autocast_ctx)을 채우고 `apply_lora(model, rank)` 뒤 LoRA 아닌 파라미터를 얼린다. `lm_checkpoint`는 끈다(몇 분이면 끝나는 학습이라 이어서 하기용 0.9GB 체크포인트를 매 epoch 쓰지 않음, DPO도 같음).
- `count_lora_params(model) -> (lora, total)`을 두고 로그에 남긴다. 결과 `out_lora/lora_identity_ko_768.pth`, 완료 줄 "완료:".
- 테스트 `LoraParamTest`: 16000 vocab 모델에 `apply_lora(rank=16)` 뒤 LoRA 파라미터 393,216개.

### Task 3: DPO 데이터와 학습 (`scripts/make_dpo_data.py`, `scripts/train_dpo_ko.py`)

- `make_dpo_data.py`: SFT 후보 질문에 greedy 생성 → `data/dpo/sft_pool_answers.jsonl`; `select_pairs(rows, answers, min_count=20) -> (pairs, stock)` → `data/dpo/dpo_pairs.jsonl`(`{"q","chosen","rejected"}`)와 `data/dpo/report.json`(상투 답 목록·횟수, 쌍 수).
- `train_dpo_ko.py`: `ChatDPODataset(rows, tokenizer, max_length)` → `__getitem__`이 원본 키(`x_chosen, y_chosen, mask_chosen, x_rejected, y_rejected, mask_rejected`) 반환, 마스크 = `ChatSFTDataset` 라벨[1:] ≠ −100. 원본 `trainer.train_dpo` 전역을 채우고 참조 모델은 시작 모델을 얼려서 쓴다. 결과 `out_dpo/dpo_ko16000_768.pth`, 완료 줄 "완료:".
- 테스트 `DpoDataTest`: 상투 답 기준 경계(19번은 제외, 20번은 포함), 정답과 같은 답 제외, 마스크 위치의 y 토큰 = 답 본문 + `<|im_end|>` + 줄바꿈. 학습 전에 쌍 0개·128토큰 초과면 멈춘다.

### Task 4: 측정 (`scripts/eval_lora_dpo.py lora|dpo`)

- `lora`: (1) 평가 12문항 "MiniMind" 포함 수 전/후 (2) 200문항 LoRA 켬 생성의 "MiniMind" 포함 수와 `generation_stats` (3) `merge_lora`로 `out_lora/merged_identity_ko_768.pth`를 만들고 대화 2,001쌍 답 본문 BPB를 최종 SFT와 비교 (4) 파라미터 수·비율, 파일 크기, LoRA로 답이 바뀐 자기소개 문항 수, 합친 모델과 켠 모델의 logit 최대 차이·데모 10문항 greedy 일치 수. 결과 `docs/09_lora_results.json`.
- `dpo`: (1) 200문항 `generation_stats` 전(docs/08 값)/후 (2) 대화 2,001쌍 답 본문 BPB·EOS 손실 비교 (3) 데모 10문항 답 전/후. 결과 `docs/09_dpo_results.json`.
