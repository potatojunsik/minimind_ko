# LoRA·DPO 체험 설계 (README 진행표 5번, 이번 공부의 마지막 단계)

작성: 2026-11-24. 아래 측정 항목과 데이터 규칙은 학습·생성 결과를 보기 전에 정했다.

## 목적

- 최종 SFT 모델(`out_final/sft/sft_ko16000_768.pth`, docs/08)에 원본 MiniMind의 LoRA와 DPO를 한 번씩 적용해 보고, 각각이 모델을 어떻게 바꾸는지 눈으로 확인한다. 성능 경쟁이 아니라 체험이며, 채택 판정은 없다.
- 끝나면 docs/09에 기록하고 README 진행표 5번을 완료로 바꾼 뒤 커밋·푸시해 이번 공부를 마친다.
- 하지 않는 것: 외부 데이터 내려받기, 설정 여러 개 비교, 원본 `minimind/` 수정, 블라인드 평가.

## 접근 (사용자 승인)

| 기법 | 가르칠 것 | 데이터 | 고른 이유 |
|---|---|---|---|
| LoRA | 자기소개 ("너는 누구야?" → "저는 MiniMind 구조로 만든 작은 한국어 모델이에요 …") | 직접 쓴 한국어 문답 약 60쌍 | 원본 MiniMind의 자기소개 LoRA와 같은 체험. 효과가 눈에 보이고, LoRA를 끄면 원래 모델로 돌아가는 것도 확인할 수 있다 |
| DPO | 상투 답 줄이기 ("그런 사람 만나지 마세요." 등) | 좋은 답 = 데이터의 정답, 나쁜 답 = 모델이 실제로 낸 상투 답 | docs/08에서 확인한 지금 모델의 가장 큰 문제를 겨냥한다 |

검토했지만 고르지 않은 것: LoRA로 위키 지식 문답 가르치기(문답을 만드는 일이 커짐), DPO 나쁜 답을 다른 질문의 답에서 무작위로 고르기(쉽지만 지금 문제와 덜 맞음).

## 공통

- 시작 모델: 최종 SFT 모델. 대화 형식·채점 위치는 `scripts/train_sft_ko.py`의 `chat_text`·`ChatSFTDataset`과 같다(답 본문 + `<|im_end|>` + 줄바꿈만 채점).
- 학습 루프는 원본(`trainer/train_lora.py`·`trainer/train_dpo.py`의 `train_epoch`, `model/model_lora.py`)을 불러 쓰고, 바깥 스크립트는 토크나이저 경로·vocab·데이터·저장 폴더만 맞춘다(`train_sft_ko.py`와 같은 방식). seed 42, bf16.
- 생성은 docs/08과 같은 greedy(`blind_chat_eval.generate_one`, 새 토큰 상한 96).

## LoRA

- 데이터 `docs/09_lora_identity_ko.json`(git에 올림, 직접 작성. `data/`는 git 제외라 docs에 둔다): 학습 48쌍 + 평가 12문항. 평가 12문항은 학습 질문과 표현이 다른 질문이다(띄어쓰기·문장부호를 무시하고 학습 질문·SFT 후보·평가 쌍과 같지 않은지 확인). 답에 담을 사실: MiniMind 구조의 작은 한국어 모델, 한국어 위키백과로 사전학습, 짧은 한국어 대화 데이터로 대화 학습, 개인 공부 프로젝트, 사실을 틀릴 수 있음. 모든 학습 답에 "MiniMind"가 들어간다.
- 설정(작성자 결정): rank 16(원본 기본), lr 1e-4(원본 기본), batch 16, 20 epoch(데이터가 48쌍이라 원본 기본 10보다 늘림), max_seq_len 128.
- 측정:
  1. 평가 12문항의 답에 "MiniMind"가 들어간 수: LoRA 전 → 후.
  2. 부작용: 07번 200문항에 LoRA를 켜고 생성했을 때 답에 "MiniMind"가 들어간 수(자기소개가 다른 대화로 새는지), docs/08과 같은 자동 집계.
  3. 부작용: 대화 평가 2,001쌍 답 본문 BPB, LoRA 켬 vs 끔(묶음 단위 쌍 부트스트랩 10,000회).
  4. 구조 확인: LoRA 파라미터 수와 비율, LoRA 파일 크기 vs 전체 가중치, LoRA로 답이 바뀐 자기소개 문항 수, LoRA를 합친(merge) 모델과 켠 모델의 출력 차이(원본 merge는 fp16으로 반올림해 저장하므로 logit 최대 차이와 데모 10문항 greedy 일치 수로 기록).

## DPO

- 나쁜 답 만들기: SFT 후보 9,749쌍의 질문에 최종 SFT 모델로 greedy 생성. 이 9,749개 답 안에서 **20번 이상 나온 같은 답**을 상투 답으로 정하고, 모델 답이 상투 답이면서 정답과 다른(띄어쓰기·문장부호 무시) 쌍만 DPO 쌍으로 쓴다(좋은 답 = 정답, 나쁜 답 = 모델 답). 평가용 2,001쌍과 07번 200문항은 쓰지 않는다.
- 설정(작성자 결정): beta 0.1, lr 1e-6, 1 epoch, batch 8, max_seq_len 128. 원본 기본 lr 4e-8은 원본의 큰 DPO 데이터 기준이라, 수천 쌍으로는 거의 바뀌지 않을 것으로 보고 키웠다. 참조 모델은 시작 모델을 고정해 쓴다(원본 방식).
- 측정:
  1. 07번 200문항 자동 집계(docs/08과 같은 기준): 상투 답 수, 서로 다른 답, 3번 이상 반복 문항, 상한에서 잘린 답. DPO 전(docs/08 값) → 후.
  2. 대화 평가 2,001쌍 답 본문 BPB와 답 끝 EOS 손실: DPO 후 vs 최종 SFT.
  3. README 대화 예시 10문항(docs/08_demo_questions.json)의 답 전 → 후.
- 예상되는 부작용: 상투 답 대신 다른 답을 반복하거나, 답이 길어지고 끝내지 못하는 일(잘린 답 증가). 그대로 기록한다.
