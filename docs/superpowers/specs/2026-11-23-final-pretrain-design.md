# 최종 사전학습 설계 (vocab 16,000)

작성: 2026-11-23. 아래 판정 기준은 두 실험과 최종 학습의 결과를 보기 전에 정했다.
결정 근거: 사용자가 승인한 추천안(학습 풀 전체, 패킹·2 epoch는 작은 실험으로 확인, 검증 세트 유지, 최종 SFT는 비교 때와 같은 설정).

## 목적

vocab 16,000 토크나이저로 최종 사전학습 모델을 만든다. 지금 있는 16,000·100만 모델(위키 검증 BPB 1.0080)보다
나아질 때만 새 모델을 쓰고, 아니면 지금 모델을 그대로 쓴다. 노트북 GPU(RTX 5050 Laptop 8GB)라 학습 시간이 비용이다.

- 목표: 시간 대비 효과가 확인된 설정만 최종 학습에 넣는다.
- 하지 않는 것: vocab 재비교, 모델 크기·lr 등 다른 설정 변경, 다른 출처 데이터 추가, 조각 경계 어텐션 마스크.
- 실패로 볼 것: 판정 기준을 결과를 본 뒤 바꾸는 것, 검증 세트가 학습에 섞이는 것, 패킹 과정에서 토큰이 빠지거나 바뀌는 것.

## 고정 조건 (06번 문서와 같음)

hidden 768, 8층, max_seq_len 512, batch 16 × accum 8, lr 5e-4 → 5e-5 (원본 cosine, 전체 step 기준), bf16, seed 42,
`train_pretrain_ko.py`의 epoch별 시드(seed + epoch)와 randperm 순서. 평가는 `eval_bpc.py`(fp32, window 512 / stride 256)로
`data/scale/heldout.jsonl` 2,001조각(1,243문서)을 재고, 평가 텍스트 sha256이 06번과 같은지 확인한다.

## 패킹 방식

- 학습 파일 순서 그대로(이미 조각 단위로 섞인 순서) 조각마다 `[bos] + 텍스트 토큰 + [eos]`를 만들어 한 줄로 이어 붙이고,
  512토큰씩 잘라 줄을 만든다. 조각은 자르거나 버리지 않는다(512를 넘는 조각도 다음 줄로 이어진다).
- 마지막 줄만 남는 칸을 pad로 채우고 loss에서 뺀다.
- 조각 경계에서 어텐션을 끊지 않는다. 위치 번호도 줄 처음부터 이어진다(일반적인 GPT식 패킹).
- 라벨: pad와 bos 위치를 -100으로 뺀다. bos는 항상 eos 바로 뒤라 맞히는 데 정보가 없어서 뺐다(작성자 결정).
  eos는 그대로 채점한다(글 끝을 아는 것도 정보, 06번 평가와 같음).
- 줄 묶음은 한 번만 만들고 epoch마다 줄 순서만 섞는다(기존 randperm 그대로). 같은 입력이면 항상 같은 줄이 나오므로 `--resume`도 그대로 쓴다.
- 확인: 줄들에서 pad를 빼고 이으면 원래 토큰 열과 완전히 같아야 한다(테스트로 고정, 학습 시작 때 줄 수·토큰 수·pad 수를 로그에 남김).

## 실험 1: 패킹 (40만, 16,000)

- 학습: `data/scale/train_400000.jsonl`을 패킹해 1 epoch. 비교 대상은 06번의 `out_scale/ko16000_n400000`(패킹 없음, BPB 1.1073).
- Δp = BPB(패킹) − BPB(기존). 문서 단위 짝 부트스트랩(10,000회, seed 0, `decide_vocab`과 같은 계산).
- **채택: Δp의 95% 구간 상한 < +0.005.** 같은 글을 약 절반 step에 학습하므로, 거의 나빠지지 않으면 채택한다.

## 실험 2: 2 epoch (20만, 16,000, 패킹 없음)

- 학습: `data/scale/train_200000.jsonl`로 2 epoch(25,000 step). lr cosine은 두 epoch 전체에 걸친다.
  1 epoch가 끝난 시점의 가중치도 따로 저장해 평가한다.
- 비교 대상(06번, 패킹 없음, 1 epoch): 20만 1.2246, 40만 1.1073.
- g = BPB(20만×1) − BPB(20만×2), G = BPB(20만×1) − BPB(40만×1). 점추정 기준 G ≈ 0.1172.
- **채택: 아래 셋 모두.**
  1. g / G ≥ 0.5 (점추정. 새 데이터를 두 배로 늘린 효과의 절반 이상을 같은 데이터 반복으로 얻음. BPB로 약 1.1659 이하)
  2. g의 95% 구간 하한 > 0 (같은 부트스트랩)
  3. BPB(2 epoch 끝) < BPB(1 epoch 끝 시점) (점추정. 두 번째 epoch에서 검증 성능이 나빠지지 않음)

## 최종 사전학습

- 데이터: 위키 학습 풀 전체 1,183,370조각(`data/scale/train_1183370.jsonl`). 06번과 같은 방법·시드로 섞은 순서라
  앞 100만 조각이 `train_1000000.jsonl`과 줄 단위로 같아야 한다(만들 때 확인). 검증 문서와의 겹침 0도 다시 확인한다.
- 패킹: 실험 1 채택이면 사용. epoch: 실험 2 채택이면 2, 아니면 1. 두 실험의 조합 효과는 따로 확인하지 않는다(한계).
- **채택: Δf = BPB(최종) − BPB(16,000·100만 기존 1.0080)의 95% 구간 상한 < 0이면 새 모델을 최종 모델로 쓴다.**
  아니면 기존 16,000·100만 모델을 쓴다.

## 최종 SFT

- 채택된 사전학습 모델에서 07번 비교와 같은 설정으로 SFT한다: Chatbot_data SFT 후보 9,749쌍, 3 epoch, lr 1e-5,
  batch 16, max_seq_len 128, seed 42. 평가용 2,001쌍은 계속 빼 둔다.
- 대화 형식 답 본문 BPB를 07번의 16,000 SFT 결과(1.1134)와 나란히 기록한다. 판정에는 쓰지 않는다.
- 새 사전학습 모델이 채택되지 않으면 07번의 16,000 SFT 모델(`out_sft/sft_ko16000_768.pth`)이 이미 같은 설정의 결과이므로 다시 학습하지 않는다.

## 실행 방식

- 실행기 `scripts/run_final.py`: 실험 1 → 실험 2 → 판정 → 최종 학습 → 판정 → 최종 SFT를 차례로 돈다.
  `run_scale.py`와 같은 방식(status.json, 락, 완료 판정 "종료 코드 0 + 완료: 줄", 끊긴 학습 이어서 하기, 평가 sha256 확인)을 재사용한다.
- 산출물은 `out_final/`(git 제외), 로그는 `logs/08_final_*.log`, 판정은 `scripts/decide_final.py`가 `out_final/decision.json`에 남긴다.
- 판정 숫자 비교는 반올림 전 값으로 한다.
