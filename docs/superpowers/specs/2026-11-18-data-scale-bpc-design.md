# 데이터 양에 따른 vocab 비교 실험 (6단계 전 추가 실험) — 설계

작성: 2026-11-18

## 목적 (왜)

- docs/05에서 위키 10만 조각, 1 epoch 조건에서는 vocab 6,400이 16,000보다 좋았다(held-out BPC 3.229 vs 3.300).
  "데이터가 많아지면 큰 vocab이 유리해진다"는 일반론이 이 규모에서도 보이는지 직접 확인한다.
- 사용자 목적은 두 가지 모두다.
  1. **결정 근거**: 4단계(SFT)에서 쓸 토크나이저(6,400 / 16,000) 선택.
  2. **경향 관찰**: 데이터 양이 늘 때 두 vocab의 BPC 차이가 어떻게 변하는지(교차점이 있는지).

## 목표 / 비목표 / 실패 조건

- 목표
  - 데이터 양 4단계(5만, 10만, 20만, 40만 조각) × vocab 2종 = 8번 학습, 같은 held-out으로 BPB(판정용)와 BPC(docs/05 비교용) 측정.
  - docs/05 한계에서 약속한 **문서 단위 학습/검증 분할**과 **토크나이저 샘플과 겹치지 않는 검증 세트** 적용.
  - 데이터 양 vs BPC 그래프 1장, 결과 표, 각 크기별 짝 비교(문서별 우세, 부트스트랩 95% 구간).
  - 결과를 docs/06 문서와 README 진행표에 기록.
- 비목표
  - 토크나이저 재학습(기존 ko_6400 / ko_16000을 그대로 쓴다. 이미 공개된 산출물).
  - 모델 구조, 학습률 등 하이퍼파라미터 탐색. 여러 시드 반복.
  - 100만 조각 전체 학습(40만에서도 교차가 없으면 그때 사용자와 추가 여부 결정).
- 실패 조건 (돌아가도 실패로 보는 경우)
  - 데이터 크기 외에 다른 조건이 섞여 바뀜(예: 작은 세트가 큰 세트의 부분집합이 아님, 크기마다 검증 세트가 다름).
  - 학습 중간 저장본을 "완료된 학습"으로 착각해 평가함.
  - 대화 컨텍스트가 끊긴 뒤 어디까지 했는지 알 수 없게 됨.

## 제약

- 노트북 RTX 5050 8GB. 제조사 성능 모드 필수(저전력 모드면 GPU 21W로 묶여 3~4배 느려짐).
- 10만 조각 1 epoch ≈ 성능 모드 기준 31~38분 → 전체 8번 ≈ 9시간 추정. 밤샘 실행 전제.
- Claude 세션(컨텍스트)이 중간에 초기화될 수 있다. Claude는 스스로 "초기화됐다"를 감지하지 못하고,
  새 세션은 메모리 파일과 디스크의 기록만 보고 이어간다. → **진행 상태는 전부 디스크에 남긴다.**
- 공개 저장소(potatojunsik/minimind_ko) 정리 규칙 유지: 데이터, 가중치는 .gitignore, 문서에 노트북 모델명 기재 금지,
  커밋/푸시는 사용자 지시 시에만.

## 접근 방식 (검토한 것)

| 방식 | 내용 | 장단점 |
|---|---|---|
| **A. 크기별 독립 학습 (선택)** | 5만/10만/20만/40만을 각각 1 epoch 처음부터 학습 | 학습률 스케줄이 매번 끝까지 가서 "데이터 N이면 BPC 얼마"가 정확. 결정 근거로 적합. 약 9시간 |
| B. 최대 데이터 1회 + 중간 저장본 평가 | 100만 1회 학습, 중간마다 BPC | 곡선은 촘촘하지만 중간 저장본은 LR이 덜 내려가 불리하게 나와 결정 근거로 약함. 약 14시간 |
| C. A + 중간 저장본 평가 | A에 중간 평가 추가 | 시간은 비슷하나 표가 복잡해짐 |

사용자가 A 선택 (2026-11-18).

## 설계 (결정된 것)

### 1. 문서 id를 붙인 데이터 다시 만들기
- `data/raw/20231101.ko`의 parquet(이미 로컬에 있음)에서 `id`(필요하면 `title`)를 함께 읽는다.
- 조각 나누기 규칙은 `prepare_kowiki.py`와 **완전히 같게**(MAX_CHARS 800, MIN_CHARS 50, 같은 순서) 해서
  `{"text": ..., "doc_id": ...}` 형식으로 저장. 새 파일의 i번째 줄 text가 기존 `kowiki.jsonl` i번째 줄과 같은지 전수 확인한다
  (같아야 "토크나이저 샘플 = 앞쪽 0~999,995줄의 5줄마다 1줄"이라는 사실을 그대로 쓸 수 있다).
- 기존 `kowiki.jsonl`, `kowiki_train_100k.jsonl`, `kowiki_heldout_2k.jsonl`은 지우지 않는다(docs/04, 05 재현용).

### 2. 검증 세트 (문서 단위, 토크나이저 샘플과 무관)
- 후보: **모든 조각이 1,000,000번째 줄 이후에 있는 문서**(토크나이저 샘플 범위 0~999,995 밖). 이 영역은 약 18만 조각.
- 후보 문서를 고정 시드로 섞어 조각 수가 약 2,000개가 될 때까지 문서 단위로 뽑는다(문서 전체 조각을 함께 넣음).
- 검증 문서의 조각은 학습 풀에서 모두 제외.
- (Claude 결정) 끝 영역 문서는 비교적 최근에 생긴 문서일 수 있어 학습 분포와 조금 다를 수 있다. 그래도 끝 영역을 쓴다.
  토크나이저가 본 글이 검증에 섞이면 vocab이 큰 16,000 쪽이 그 글을 더 잘 외워 유리해질 수 있으므로,
  두 vocab의 상대 비교에는 토크나이저와의 독립이 더 중요하다. 이 치우침은 docs/06 한계 절에 적는다.

### 3. 학습 세트 (중첩)
- 학습 풀 = 전체 조각 − 검증 문서 조각.
- 학습 풀을 고정 시드로 **한 번** 섞고 앞에서 5만/10만/20만/40만을 자른다 → 작은 세트는 항상 큰 세트의 앞부분(중첩).
  파일 앞쪽 치우침 문제도 같이 해결.
- 학습 jsonl에는 `text`만 있어도 됨(원본 PretrainDataset 호환). doc_id는 분할 확인용 별도 파일로.

### 4. 학습
- `scripts/train_pretrain_ko.py`를 그대로 사용. 설정은 docs/05와 동일
  (hidden 768, layer 8, max_seq_len 512, batch 16, accum 8, lr 5e-4, seed 42, bf16, 1 epoch).
- 실행별 출력 폴더를 분리: 예 `out_scale/ko6400_n50k/`. 로그는 `logs/`에 실행별 파일.
- 실행 순서: 크기 작은 것부터, 크기마다 6,400 → 16,000 (중간에 멈춰도 앞 크기의 짝 비교는 완성되도록).

### 5. 끊겨도 이어가는 실행기
- 실행기 스크립트 하나가 8개 학습 + 각 평가를 순서대로 돌린다.
- **완료 판정은 가중치 파일 존재가 아니라 완료 표시 파일**로 한다
  (원본 train_epoch이 save_interval마다 같은 이름으로 가중치를 덮어쓰므로, 파일이 있어도 학습 중일 수 있다).
  프로세스가 정상 종료(종료 코드 0)하고 로그에 "완료" 줄이 있을 때만 `DONE` 표시 + 결과 기록.
- 다시 실행하면 완료된 것은 건너뛰고, 중단된 실행은 처음부터 다시 학습(최대 손실은 40만 1회 ≈ 2.5시간, 감수).
  - 2026-11-19 실행 중 변경: 16,000·100만이 블루스크린으로 끊긴 뒤, 학습 중에 끊긴 실행은 체크포인트(1,000 step마다)에서 이어서 학습하도록 바꿨다(`--resume 1`, [docs/06 실험 조건](../../06_데이터양_비교.md#실험-조건)).
- 진행 상황 파일(예: `out_scale/status.json` 또는 결과 jsonl)에 실행별 상태, 시작/종료 시각, BPC를 기록.
- 실행기는 Claude 세션과 무관하게 계속 돌아야 한다(세션이 끊겨도 학습이 죽지 않도록 별도 창/프로세스로 띄움).
- 메모리 파일(minimind-ko-study.md)에 "실험 진행 중, 상태 파일 위치, 재개 방법"을 적어 둔다.

### 6. 평가와 정리
- 각 학습 직후 `eval_bpc.py --data_path <새 검증 세트> --per_doc_out ...` (window 512, stride 256 기본값 유지).
- 크기별로 `paired_compare.py`로 6,400 vs 16,000 짝 비교.
- (Claude 결정) 검증 세트는 한 문서의 조각을 전부 넣으므로 조각끼리 상관이 있다. 부트스트랩은 **위키 문서 단위**로 다시 뽑는다
  (조각 단위로 뽑으면 95% 구간이 실제보다 좁게 나옴). 검증 jsonl의 doc_id를 줄 순서로 결합하는 계산은 판정 스크립트(`decide_vocab.py`)에 두고,
  `paired_compare.py`는 docs/05 재현용으로 그대로 둔다(같은 기능을 두 곳에 만들지 않기 위해 계획 단계에서 변경). 문서별 우세 비율은 조각 단위와 문서 단위를 둘 다 적는다.
- 그래프: x = 학습 조각 수(로그 축), y = held-out BPC, vocab별 선 2개 → `images/`.
- 결과 문서 `docs/06_데이터양_비교.md`(docs/05 형식 따름), README 진행표·실험 표 갱신.
  docs/05 한계 절에 "→ docs/06에서 문서 단위 분할로 다시 측정" 연결.

### 7. 판정 규칙 (사용자 확정, 2026-11-18 — 결과 보기 전에 고정)
- **지표**: 같은 한국어 검증 문서에서의 **BPB**(bits per UTF-8 byte) = 총 NLL / ln2 / 총 UTF-8 바이트 수.
- **Δ = BPB(6,400) − BPB(16,000)**. Δ > 0이면 16,000이 앞선다. (docs/05의 "16,000 − 6,400"과 부호가 반대이므로 문서에 명시)
- **신뢰구간**: 위키 문서 단위로 같은 문서를 두 모델에 쌍으로 묶어 복원추출(부트스트랩), 95% 백분위 구간.
- 판정 (40만 조각 결과 기준, 위에서부터 차례로 적용):
  1. Δ(40만)의 95% 구간 하한 > 0 → **16,000 선택**.
  2. Δ(40만) 점추정 < 0 이고, `Δ(40만) − Δ(20만)`의 95% 구간 하한 > 0 → **100만 조각 실험 추가 여부를 사용자에게 먼저 묻는다** (Claude가 임의로 시작하지 않음).
     이 차이의 구간은 같은 검증 문서를 한 번에 뽑아 네 모델(20만·40만 × 2 vocab)에 똑같이 적용해 구한다.
  3. 그 밖의 경우 → **6,400 선택**. (Δ(40만) 점추정이 양수여도 구간에 0이 포함되면 여기에 해당)
- 이번 8개 가중치는 비교용이다. 최종 모델은 선택한 토크나이저로 새로 사전학습하고, SFT도 같은 토크나이저를 쓴다.
- (Claude 결정) 부트스트랩 횟수는 10,000회, 시드 고정. 판정은 BPB로 하고, docs/05와 이어 보기 위해 BPC도 표에 함께 적는다
  (같은 검증 문서에서 두 모델의 바이트 수, 글자 수는 같으므로 Δ의 부호는 BPB와 BPC가 같고 크기만 비례해서 다르다).
- (Claude 결정) `eval_bpc.py --per_doc_out`에 문서별 UTF-8 바이트 수를 추가하고, 판정 계산은 별도 스크립트(예: `scripts/decide_vocab.py`)로 만들어
  상태 파일의 결과로 판정 결과(1/2/3 중 어디인지와 수치)를 출력한다.

#### 7-1. 100만 조각 추가와 최종 선택 (판정 2 결과로 추가, 사용자 확정 2026-11-19 09:00 — 100만 결과 확인 전)
- 40만 판정 결과: 판정 2 (Δ(40만) −0.0027 [−0.0042, −0.0012], `Δ(40만) − Δ(20만)` +0.0140 [+0.0125, +0.0157]). 사용자가 100만 조각 실험을 승인했다.
- 100만 학습 파일은 같은 시드로 섞은 학습 풀의 앞 100만 조각이다 (앞 40만은 기존 `train_400000.jsonl`과 같음). 검증 세트와 설정은 그대로다.
- `Δ(100만) = BPB(6,400) − BPB(16,000)`, 기존과 같은 문서 단위 쌍 부트스트랩으로 95% 구간을 구한다.
- 구간 하한 **> 0 이면 16,000**, **≤ 0 이면 6,400**을 선택한다. 경계값은 반올림 전 수치로 판정한다.
- `Δ(100만) − Δ(40만)`과 그 95% 구간은 경향 설명용으로만 보고한다. 토크나이저 비교 실험은 100만에서 마무리한다.
- 구간에 0이 포함되면 결과에 "16,000의 우위가 확인되지 않아 사전 규칙에 따라 6,400을 선택했다"고 적는다.
- 선택한 토크나이저로 최종 모델을 새로 사전학습하고 SFT까지 이어간다.

### 8. 구현 확인 사항 (사용자 지정, 2026-11-18 승인 시)
- **BPB 계산**: 평가한 원문의 총 손실(비트) ÷ 총 UTF-8 바이트 수. 문서별 BPB의 평균이 아니다.
  부트스트랩 10,000회에서도 매번 뽑힌 문서들의 손실 합과 바이트 수 합을 각각 구해 나눈다. BPC는 같은 손실 합 ÷ 총 글자 수.
- **검증 분리는 원문 문서 단위**: 조각으로 나누기 전에 원문 문서(doc_id)로 검증/학습을 가른다.
  그다음 실제로 확인한다(구성상 겹치지 않아야 하지만, 텍스트 대조로 검증한다):
  - 검증 문서의 어떤 조각도 `data/tokenizer_sample.jsonl`(두 토크나이저 공통 학습 샘플)에 없음.
  - 검증 문서의 어떤 조각도 이번 학습 세트 4개(5만~40만)에 없음. 같은 원문의 다른 조각도 없음(doc_id 기준).
  - 참고로 기존 `kowiki_train_100k.jsonl`과의 겹침도 세어 기록(기존 모델을 비교에 쓰지는 않음).
  - 확인 결과(겹침 0개)는 docs/06에 수치로 적는다.
- 모델마다 한 번씩 학습하므로 결과표 아래에 "95% 신뢰구간은 검증 문서 표본에 따른 변동을 나타낸다"를 한 줄 적는다
  (학습 시드에 따른 변동은 포함하지 않는다).
- 판정 2번 조건이 충족되면 100만 조각 실험은 시작하지 않고 사용자에게 먼저 묻는다.
