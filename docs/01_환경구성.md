## 설치 순서

[uv](https://github.com/astral-sh/uv)로 기존 Python을 건드리지 않고 프로젝트 전용 환경을 만든다. 시스템 Python(3.14)은 그대로 두고, 라이브러리 호환성 때문에 프로젝트에서는 3.11을 쓴다.

> **명령 실행 환경 안내 (모든 문서 공통)**
> - 문서의 명령은 **Windows 명령 프롬프트(cmd)** 기준이다. 경로 구분자 `\`, 줄 이어쓰기 `^`는 cmd 문법이다.
> - `D:\minimind_ko`는 이 기록에서 쓴 **작업 폴더 예시**다. 다른 위치에 만들어도 된다.
> - 다른 드라이브로 이동할 때는 `cd /d D:\minimind_ko`처럼 `/d`를 붙인다 (cmd에서 `/d` 없이 `cd D:\...`를 하면 드라이브가 바뀌지 않는다).
> - Git Bash에서 실행할 때는 경로를 `/`로 바꾸고(`.venv/Scripts/python.exe`, `cd /d/minimind_ko`), 줄 이어쓰기는 `^` 대신 `\`를 쓴다. Git Bash에서 `\`가 들어간 경로를 그대로 쓰면 이스케이프 문자로 처리돼 실행되지 않는다.

```bat
REM 1. 작업 폴더와 원본 저장소
mkdir D:\minimind_ko
cd /d D:\minimind_ko
git clone https://github.com/jingyaogong/minimind.git
cd minimind
REM 이 기록에서 사용한 커밋
git checkout 233d00fa068ec2b8c0d4f07b703934d6391a5a73
cd ..

REM 2. Python 3.11 가상환경
uv venv --python 3.11 .venv

REM 3. PyTorch (RTX 50 시리즈는 CUDA 12.8 이상 빌드가 필요)
uv pip install --python .venv\Scripts\python.exe torch torchvision --index-url https://download.pytorch.org/whl/cu128

REM 4. 나머지 의존성 (requirements.txt에는 torch가 주석 처리되어 있음)
uv pip install --python .venv\Scripts\python.exe -r minimind\requirements.txt peft

REM 5. pyarrow 버전 고정 (아래 "겪은 문제" 참고)
uv pip install --python .venv\Scripts\python.exe "pyarrow==20.0.0"
```

설치된 주요 버전: `torch 2.11.0+cu128`, `transformers 4.57.6`, `tokenizers 0.22.2`, `datasets 3.6.0`, `numpy 1.26.4`, `pyarrow 20.0.0`, `peft 0.21.3`

> 위 순서 대신, 정리 시점에 고정해 둔 [requirements-lock.txt](../requirements-lock.txt)로 똑같은 버전을 한 번에 설치할 수도 있다. 명령은 [README](../README.md#0단계) 참고.

### GPU 동작 확인

[scripts/check_gpu.py](../scripts/check_gpu.py)로 PyTorch가 GPU를 인식하는지 확인하고, bf16 행렬곱(4096×4096, 50회) 속도를 대략 측정한다. 학습 중이 아닐 때 실행한다.

```bat
cd /d D:\minimind_ko
.venv\Scripts\python.exe scripts\check_gpu.py
```

실행 결과 (학습이 없을 때, 노트북 성능 모드):

```
torch 2.11.0+cu128
CUDA available: True
GPU: NVIDIA GeForce RTX 5050 Laptop GPU | capability (12, 0)
VRAM: 8.0 GB
bf16 matmul: 23.8 TFLOPS
```

- 환경 구성 당시 처음 측정한 값은 **10.9 TFLOPS**였다. 그때는 워밍업 없이 측정했고, 노트북의 제조사 전원 모드를 확인하지 않았다. 나중에 이 노트북은 제조사 성능 모드가 아니면 GPU 전력이 21W로 묶인다는 것을 알았으므로([04번 문서](04_한국어_사전학습.md#겪은-문제)), 첫 측정은 저전력 상태였을 가능성이 있다.
- 노트북에서 측정값이 낮게 나오면 Windows 전원 설정뿐 아니라 제조사 성능 모드도 확인한다.

## 원본 모델 받기와 테스트

모델은 `minimind\minimind-3` 폴더에 받는다 (`minimind\` 폴더 전체가 git 제외 대상이라 저장소에는 없다).

```bat
cd /d D:\minimind_ko\minimind
..\.venv\Scripts\python.exe -c "from huggingface_hub import snapshot_download; snapshot_download('jingyaogong/minimind-3', local_dir='minimind-3')"
..\.venv\Scripts\python.exe -X utf8 ..\scripts\test_chat.py ./minimind-3
```

### 결과: 토크나이저 효율

| 문장 | 글자 수 | 토큰 수 |
|---|---|---|
| 오늘 날씨가 정말 좋네요. | 14 | **30** |
| 今天天气真好。 | 7 | 5 |
| The weather is really nice today. | 33 | 9 |

- 토크나이저 어휘 수는 6,400개이고, 중국어와 영어 위주로 만들어져 있다.
- 한국어는 사전에 단어가 없어서 **바이트 단위로 쪼개진다** (한 글자 = 3바이트 → 토큰 여러 개).
- 같은 길이의 문장을 학습해도 한국어는 토큰이 훨씬 많아서, 학습 효율과 품질이 크게 떨어진다.

## 배운 점

- LLM이 어떤 언어를 잘하려면 **그 언어에 맞는 토크나이저**와 **그 언어로 된 학습 데이터**가 둘 다 필요하다.
- 64M 정도의 작은 모델도 학습한 언어(중국어)로는 그럴듯하게 대화한다.
- 다음 단계에서 한국어 토크나이저를 새로 만드는 이유가 여기서 확인됐다.

## 겪은 문제

| 문제 | 원인 | 해결 |
|---|---|---|
| 토큰 출력 시 `UnicodeEncodeError: 'cp949' codec can't encode character '\xec'` | Windows 콘솔 기본 인코딩이 cp949다. 한글 자체가 아니라, 정리 전 테스트 코드에서 토큰을 바이트 조각 그대로(`convert_ids_to_tokens`) 출력할 때 나오는 문자(예: `ì`, U+00EC)가 cp949에 없어서 생긴 오류 | `python -X utf8`로 실행 |
| `generate()`에서 `token_type_ids` 오류 | 토크나이저가 만든 `token_type_ids`를 모델이 받지 않음 | `tok(..., return_token_type_ids=False)` |
| 학습 시작 시 `pyarrow requires NumPy 2.0 or newer` | requirements.txt가 `numpy==1.26.4`로 고정돼 있는데, `datasets`가 최신 `pyarrow 26`을 같이 설치함 | `pyarrow==20.0.0`으로 낮춤 (NumPy 1.x 지원) |
